HPX V2.0.0 (Oct 31, 2026)#

HPX V2.0.0 is one of the largest releases in the project’s history, touching the language baseline, the execution model, the networking layer, the build system, and observability tooling. The inventories below cover over 700 pull requests with merge commits in the release comparison, two additional PRs incorporated through transplanted changes, and more than 150 closed milestone issues. The sections below expand on each major theme.

This release is the result of a broad community effort. Since V1.11.0, roughly 100 contributors have authored more than 4,000 commits, and over 80 of them made their first contribution to HPX during this release cycle. We are grateful to everyone who contributed code, documentation, tests, bug reports, and reviews. Your work made this release possible.

Language and Standard Baseline#

  • C++20 is now the minimum required standard, up from C++17. V1.11.0 was the last release to support C++17 (Issue #5497).

  • Compared with the 1.11 release branch, the minimum supported GCC version rises from 11 to 12, and Visual Studio from 2019 to 2022. The minimum Clang version remains 16.

  • Base builds require CMake 3.18 or newer. The prerequisite table has been corrected to match the enforced minimum; C++20 module builds require a newer CMake version as described below.

  • A large volume of obsolete #if/feature-test guards that existed only to support pre-C++20 compilers were removed (Issue #6941), simplifying the codebase now that C++20 is guaranteed.

C++20 Modules#

Native C++20 module support was added across the HPX module hierarchy (Issue #6014). It is optional: HPX_WITH_CXX_MODULES defaults to OFF. Enabling it requires CMake 3.28 or newer, a Ninja or Visual Studio generator, and GCC 14+, LLVM Clang 16+, or Visual Studio 17.4+. AppleClang is rejected by the module configuration checks.

C++26 Adoption (Ahead of Standardization)#

Adopted early via reflection and experimental compiler support:

HPX adopted several not-yet-finalized C++26 features early, using experimental compiler support, well ahead of formal standardization:

  • Reflection-based serialization - arbitrary user types can now be serialized without hand-written serialize() member functions, using compile-time reflection to enumerate members automatically.

  • Reflection-driven actions and components - a large family of new reflection APIs replaced macro-heavy boilerplate:

    • reflect_action integrated with basic_action (PR #7281), including direct actions (PR #7349), component actions (PR #7311), and auto-registration (PR #7298).

    • reflect_client and the HPX_REFLECT_CLIENT macro for reflection-based client types (PR #7385), with hpx::launch::sync overload support (PR #7417).

    • hpx::async<^^func>(target, ...)-style reflection overloads (PR #7376), plus reflection overloads threaded through async_distributed (sync, post, dataflow, async_continue, launch-policy variants: PR #7509, PR #7515, PR #7523, PR #7462).

    • Example programs migrated to demonstrate the new API: factorial_reflection (PR #7508), fibonacci_reflection (PR #7455).

    • A migration guide (PR #7348) and compile-time overhead benchmarks comparing macros vs. reflect_action (PR #7332, PR #7459) were added to help users and maintainers evaluate the transition.

  • Early contract support - HPX API functions have begun to be annotated with C++26 contract preconditions/postconditions, starting with sorting and heap algorithms (PR #7434).

Senders/Receivers Overhaul#

HPX’s original, home-grown implementation of P0443/P1897/P2300 (Issue #5045) has been removed entirely and replaced by stdexec (NVIDIA’s reference implementation) as the sole senders/receivers foundation, usable from both C++20 and C++26:

  • Multiple correctness/compliance passes: fixing P2300 compliance and set_stopped handling for any_sender (PR #7453), get_allocator query support for schedulers (PR #7320), allocator support for when_all_vector (PR #7346), and get_completion_domain advertisement on run_loop (PR #7276).

  • Distributed and accelerator adaptors were updated to integrate cleanly with stdexec: async_mpi (PR #7341, PR #7318, PR #7277), async_cuda (PR #7330, PR #7374), and the fork-join executor (fixing truncation bugs on large ranges, Issue #6922). Distributed sender/receiver facilities were also moved into their own module (PR #7396) with dedicated distributed test coverage (PR #7402, PR #7354).

  • Algorithm-level sender/receiver support was extended to more algorithms, e.g. set_intersection (PR #7365), set_difference (PR #7344), and shift_left/shift_right (PR #7296).

  • Miscellaneous but important bug fixes: a lifetime race in sync_wait’s notify path (PR #7394), a silent hang in make_future with run_loop_scheduler (PR #7437), and a future/promise bridge redesign (PR #7355).

Runtime and Execution APIs#

  • The P2079 parallel scheduler integrates sender work with HPX thread pools (PR #6655). hpx::execution::experimental::get_parallel_scheduler() uses the default pool; the overload taking a pool reference supports named pools obtained through hpx::resource::get_thread_pool (PR #7579).

  • Execution-policy traits and the independent rebind_policy_executor_t / rebind_policy_parameters_t utilities support inspecting and adapting policies (PR #7550, PR #7551).

  • Thrust integration adds HPX execution policies for Thrust algorithms in CUDA builds (PR #6744), controlled by HPX_WITH_THRUST.

  • New concurrent containers include vector, queue, unordered map, and unordered set (PR #6897).

  • hpx::local::termination_detection waits for local work to finish, with timeout, deadline, and stop-token cancellation overloads (PR #6886, PR #6890).

  • hpx::threads::set_thread_affinity and hpx::this_thread::set_affinity expose thread-affinity control (PR #6861).

  • finalize and disconnect accept std::chrono durations through new overloads (PR #7612).

  • hpx::agas::set_rpc_timeout now rejects positive durations shorter than one millisecond: it returns false and leaves the stored timeout unchanged instead of storing a zero-millisecond timeout.

  • HPX::init supports runtime initialization from libraries, and HPX::auto_wrap_main starts the runtime around main() without requiring the wrapping header (PR #6775, PR #6804). HPX::auto_wrap_main is also supported with MSVC (Issue #7662, PR #7664). Local initialization was decoupled from the distributed runtime (PR #7103).

tag_invoke Removal#

A systematic, multi-PR effort removed tag_invoke-based customization across nearly every layer of the library, replacing it with plain member functions - this is one of the more consequential breaking changes for downstream code that customized HPX behavior via ADL/tag_invoke:

  • Core execution layer (PR #7368), executor CPOs (PR #7319), container algorithms (PR #7395), and parallel algorithms broadly (PR #7380, PR #7301).

  • Specific customization points converted to members, e.g. connect_t (PR #7292).

  • Cleanup of now-stale hpx_tag_invoke module dependencies (PR #7451) and a final sweep (PR #7443).

Networking / Parcelport Work#

  • A new, optimized MPI parcelport, with orderly teardown that quiesces before MPI_Finalize (PR #7404).

  • An optimized LCI parcelport.

  • A separate LCW/MPIx parcelport was added (PR #6815), enabled with HPX_WITH_PARCELPORT_LCW=ON (default OFF).

  • Substantial AGAS/parcelset hardening:

    • force_disconnect support for removing crashed/unreachable localities, including races between disconnect completion and AGAS resolve visibility (Issue #7483, PR #7490, PR #7491, PR #7447).

    • Dijkstra termination detection improvements, including probe retry bounding and cursor restart per probe (PR #7496, PR #7516, PR #7495).

    • Connection/communicator caching fixes, e.g. avoiding communicator reuse between collectives/scan test phases (PR #7526, PR #7364) and caching channel communicators per site (PR #7481).

    • Disconnected-locality handling, including a dedicated dispatch guard (PR #7536) and correct error handling in resolve_locality (PR #7388).

    • A fix for the shared-pointer serialization type-confusion / deserialization vulnerability reported in Issue #7333 (PR #7334).

Observability / Tracing#

  • A new, minimal tracing abstraction layer, hpx::tracing (Issue #7049), unifying the Intel ITT API (Intel VTune) and Tracy backends behind one API, with APEX also unified under it (PR #7293).

  • Tracy support was added as a first-class profiler backend, including causal tracing (PR #7423), fiber support activation (Issue #6989), and per-subsystem event gating for overhead control (PR #7529).

  • Instrumentation was added broadly: schedulers and work-stealing (PR #7450), background work and OS-thread sleep events (PR #7484), parcel send/receive (PR #7511), future continuations (PR #7403), task lifecycle events (PR #7347), suspend/resume hooks (PR #7372), data-parallel workloads (PR #7392), and general runtime instrumentation (PR #7357).

  • LIKWID profiling support was added (PR #6053), enabled with HPX_LIKWID_WITH_LIKWID=ON.

  • New tooling built on top of this infrastructure: hpx-top, an interactive TUI performance monitor (Issue #7001), and hpx_stat_viewer; both scripts are now installed (Issue #7656, PR #7658).

  • A distributed-observability prototype (“HPX-Vision”) was proposed and discussed (Issue #7225) as a longer-term direction beyond this release.

  • The Intel ITT API tracing backend now provides a shared domain, regions, and markers (PR #7636). The Tracy targets are exported so that consumers can find them through HPX (PR #7654), and Tracy export annotations were moved off class heads to build with GCC 11 and 12 (PR #7669).

Collectives Infrastructure#

Hierarchical collectives were built out and hardened substantially this cycle:

  • New hierarchical primitives: all_reduce (with the reduction seed now moved instead of copied, PR #7398), all_gather/scatter (flattened payloads, PR #7375), all_to_all (flattened exchange payloads PR #7377, hierarchical implementation PR #7307, size-based pairwise dispatch PR #7431, and a ~66x performance regression fix for the flat variant, Issue #7411), and a hierarchical scan collective (PR #7343).

  • Validation and robustness hardening across collectives, including rejecting explicit generations mixed with auto-generation (PR #7369), unifying generation handling across collective types (PR #7326), and broad input-validation/tree-coverage hardening (PR #7321, PR #7359).

  • hpx::distributed::barrier was reimplemented on top of the collectives infrastructure rather than its own ad hoc protocol (Issue #7203).

Supervision Module#

A new lifecycle/observability subsystem, “supervision,” was introduced for managing dispatch of distributed work under crash/partial-failure conditions:

  • Core infrastructure for lifecycle events and observers (PR #7399), a dispatch component (PR #7413), and admission control (PR #7409).

  • Fenced dispatch support (PR #7425), dispatch locality and join epoch handling (PR #7438), and target resolution (PR #7427), plus general dispatch fixes and cleanup (PR #7457).

  • A reflection overload for dispatch_work was added consistent with the broader C++26 reflection push (PR #7432).

Parallel Algorithms#

A large, ongoing wave of standard-conformance and correctness work across the parallel algorithms library:

  • C++20/23 conformance: fixing sentinel return-type mismatches in hpx::ranges container CPOs (PR #7322), unifying projection support across starts_with/ends_with (PR #7314), and adding projection coverage for unique/unique_copy (PR #7393) and minmax_element (PR #7230).

  • New algorithms: hpx::experimental::for_each_index per P4150 (Issue #7214), hpx::ranges::iota (Issue #6969), find_last/find_last_if/find_last_if_not (Issue #6892), and the C++23 fold family: fold_left, fold_right, fold_left_first, fold_right_last, fold_left_with_iter, and fold_left_first_with_iter (PR #6884, PR #6910).

  • Correctness fixes: max_element returning the last, rather than first, greatest element (PR #7304), two bugs in chunk_size.hpp involving swapped arguments (Issue #6931), an incorrect single-segment subrange handling bug in segmented scan (Issue #7052), and non-preserved sequenced semantics in parallel uninitialized_relocate for overlapping ranges (Issue #6878).

  • Proxy/iterator support: proxy support for find algorithms (Issue #6719), unwrapping contiguous iterators (Issue #6729), and conditional special member functions for zip_iterator (Issue #6752).

  • Distributed segmented merge: added merge support for segmented input and output ranges distributed across localities, with sequential, parallel, and task execution policies (PR #7545).

  • Datapar/SIMD: fixing EVE - the Expressive Vector Engine/simd unaligned load/store broadcast bugs (PR #7435, Issue #7287), and guarding a mismatched SIMD path on zip_iterator compatibility (PR #7328).

  • Fixed-size SIMD policies: added hpx::execution::fixed_size_simd<N> and hpx::execution::par_fixed_size_simd<N> (plus their task variants) to select vector lane counts explicitly. Datapar loops and algorithms use the policy’s lane count, exposed through hpx::execution::policy_traits. Existing SIMD policies retain the native lane count (PR #7674).

Scheduler / Threading Improvements#

  • NUMA-aware work stealing: a distance-aware scheduling feature (Issue #7091), plus fixes for suspended-processing-unit handling in NUMA-aware scheduling (Issue #6963) and reduced lock contention via randomized victim selection (Issue #6904).

  • Queue performance: SPSC queue performance work for the work-requesting scheduler (Issue #7112), and comparative benchmarking / hardening of the MPMC queue (Issue #7167), plus a fix for a race condition in lockfree::deque::empty() (Issue #7158).

  • Memory/lifetime fixes: memory accumulating while iterating with a sliding semaphore (Issue #7185) and while creating tasks (Issue #7150); better lifetime management for background/pool threads (PR #7350); thread-data size reductions (PR #7379); and batched atomic decrements in thread_queue::cleanup_terminated_locked() (Issue #7085).

  • Fork-join executor: fixed silent truncation for ranges larger than 2^32 (Issue #6922).

  • Shared priority scheduler: the scheduler now creates a new thread when one is requested (Issue #5189, PR #7682).

  • Fork dispatch: fixed hpx::launch::fork tasks remaining unscheduled when launched from a plain OS thread or an HPX thread in another pool. Both post and async now schedule the task directly when an immediate handoff is unavailable (PR #7687).

Breaking changes#

The items below require changes in user code. Each is covered in more detail in the sections above.

  • C++20 is now the minimum required standard. Compiling HPX or applications using it with C++17 is no longer supported.

  • The minimum supported compiler versions have changed. Please see our Prerequisites page for the current support matrix.

  • The use of tag_invoke for API customization has been removed where possible. Code that relied on overloading HPX functionality through tag_invoke will have to be adapted.

  • Our own, by now outdated, implementation of std::execution (senders and receivers) has been removed. It is replaced by the reference implementation (stdexec).

  • hpx::experimental::for_loop_n_strided now invokes the loop body exactly n times, as required by N4755, 7.2.4, paragraph 2.1. It used to read n as the distance to cover and invoked the body ceil(n / stride) times instead, so code that scaled n by the stride to work around this has to stop doing that.

  • Negative strides are no longer supported by hpx::experimental::for_loop_strided, hpx::experimental::for_loop_n_strided and hpx::ranges::experimental::for_loop_strided. N4755, 7.2.4, paragraph 2.1 only describes a forward traversal, so the stride is now required to be positive.

  • A live-out induction variable handed to one of the strided for_loop algorithms is now advanced by the number of iterations instead of by the distance those iterations cover. The value it ended up with used to be too large by a factor of the stride.
